# 排障工作流

1. 先确认版本与现象；用户没给版本时先问一句，不要假设。
2. 用 `searchDocs` 检索错误关键词或功能名（中英文都试一次）。
3. 按“最可能 → 次可能”给 2–3 个原因，每个原因都附一个可执行的验证方法。
4. 给出最小修复步骤；命令、权限节点和 YAML 保持原文。
5. 如果文档不足，明确说明还需要哪些信息（版本、完整报错、相关 config 片段）。
6. 不要建议删除数据库或重装，除非文档明确要求。
